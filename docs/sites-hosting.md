# LedgerAlpha hosted Site

The `site/` application is the private, cross-device edition. The original Next/Prisma application remains a local prototype at the repository root. Do not expose that original unauthenticated local server to the internet. Its old import/valuation routes are not the hosted write path; the hosted edition uses the validated service described here.

## Runtime and identity

Vinext renders React on a Cloudflare Worker through the supported Sites starter. Sites provides the hosted URL and ChatGPT sign-in/access boundary. The Site starts owner-private. Authentication does not depend on the operator's computer, and there are no custom passwords, brokerage connections or API keys to configure. Every protected API calls the server identity helper before accessing data. D1 reads/writes scope by the Site-specific authenticated user ID. Cross-origin and non-JSON mutations are rejected. Source code can be public while the hosted application remains private.

The starter simulates a synthetic identity only in loopback development; that integration is absent from production builds. Never add a hosted auth bypass or put identity/credentials into browser code. Site sharing is managed by the platform; the app does not invite others. Partners are economic owners of the pooled account, not login identities. Additional Site visitors would get their own isolated ledger, not shared access to the owner's financial records.

## Durable storage and transactions

`.openai/hosting.json` declares the D1 `DB` binding. Sites provisions D1 and applies the schema-only migration in `site/drizzle/`; local preview uses a separate `.wrangler/state` database. No seeds or destructive reset endpoints run on production.

A `ledgers` row contains one user's versioned JSON ledger. Each mutation validates the whole candidate history, resolves necessary event-date prices, replays units/FIFO and performs an atomic revision-checked write. A competing stale browser receives HTTP 409. Command keys and content hashes make uncertain retries safe; a changed payload under a previously saved key is rejected. CSV external row identities additionally prevent repeated imports. Stable occurrences preserve identical rows within one file. Recognized Robinhood source identities are independent of editable owner attribution; legacy normalized identities remain recognized for compatibility. Generic CSV identities include the cash-flow partner.

D1 batch transactions save the prior revision into `ledger_backups` and update the current row together. The last 20 prior revisions are retained per user. Public Yahoo prices and sync metadata live in separate `market_cache`/`market_sync` tables. Deploying a new Worker does not reset the D1 ledger. Applied migrations are immutable; add new migrations for future schema changes.

This document model is intentionally bounded to a personal ledger: at most 5,000 entries and 1.5 MB serialized data, with up to 20 economic partners. Each CSV batch supports 2,000 rows / 1 MB. Splitting large CSV files into chronological batches is supported; identical activity across overlapping exports should be reviewed because broker CSVs may not contain unique transaction IDs. Manual entry remains available for ambiguous rows.

## Accounting and imports

The canonical pure accounting code lives in `site/lib/core/`; root `lib/accounting/`, domain types and normalizer re-export it, so local and hosted tests cover the same engine. The hosted `lib/ledger/engine.ts` validates positive cash-flow units, sufficient cash, ownership and asset quantities. It computes allocations in a streaming chronological replay. Same-day events retain entry order, with splits applied first. A 4:1 split is ratio `4`, never four additional shares; Robinhood added-share rows are converted once to a ratio. Known absent historical splits are inferred only when positive shares are outstanding immediately before the event, after earlier trades and splits. An event is identified by symbol/date as well as its split ratio: an equivalent later CSV row is marked already represented and cannot apply a second split; conflicting records are blocked for explicit reconciliation. Manual entries must edit an existing same-day event instead of adding another. Split origin is retained, with compatibility for earlier generated event IDs. Manual adds/edits re-evaluate known inferred events across the resulting history: a backdated full sale removes an obsolete inference, while reopening a partial position restores the applicable known inference. Added/removed inferred events are reported after the save and remain visible in transaction history. Restore only prunes obsolete inferred records already in the backup; it does not invent missing corporate actions. Explicit manual/CSV actions are never discarded to make an inconsistent correction pass. Reverse-split CSV share reductions require a verified manual ratio entry.

Deposits issue and withdrawals redeem positive quantities of units. Historical share prices are keyed by symbol. Cash-flow unit pricing uses the most recent daily close on or before the event within seven days, never a later trading day's close or an invented cost-basis price. Yahoo split-adjusted historical prices are converted back to event-day raw share prices for actual holdings/NAV. A manually verified pre-flow portfolio value can override daily-close estimates for intraday events or missing data. Saved event prices are retained; adding or editing a backdated entry recalculates subsequent ownership and blocks if required valuations are absent. Backups preserve those valuation inputs.

FIFO tracks each sale's cost basis at the sale, so later splits cannot rewrite already realized basis. Net contributions are distinct from remaining lot basis. Portfolio gain includes realized results, dividends and fees; per-decision grades compare price returns and actual FIFO sale proceeds with SPY or QQQ price returns, excluding dividends. Missing/stale grading inputs leave the grade unavailable.

CSV preview parses complete logical CSV records (including quoted multiline descriptions) and preserves row errors, duplicates and explicit nonfinancial/paired-row notices. The recognized Robinhood informational footer is allowed its additional field only when the transaction fields are empty and the exclusion notice matches; malformed financial rows remain errors. Activity Date takes precedence over process/settlement dates. Source order is selectable. Automatic mode recognizes descending date order and treats a single-day Robinhood file as newest-first; it reverses that order for replay, retains original record numbers and displays the same-day assumption. Operators can explicitly preserve oldest-first order instead. No trade-time chronology is inferred from balances. Every cash flow needs an owner, with per-row choices and an optional default. No owner is selected automatically. Trades remain shared pool assets.

Supported hosted events are deposit, withdrawal, buy, sell, dividend, fee, split, simple paired conversion, option expiration and noncash reward. Options use canonical contract symbols, never underlying stock positions. Quantities remain contracts; holdings, pre-flow NAV, core valuation, active decision values and performance-series NAV multiply quoted premium by a separately verified premium multiplier. Standard equity/ETF terms require 100; adjusted/other terms require an explicit positive multiplier and verification source. A symbol or cash/premium ratio alone does not verify terms. Existing/CSV options without verified terms remain unknown: active totals and grades are unavailable, and cash-flow replay requires verified terms or a verified total pre-flow NAV override. Closed option cash results remain usable. Metadata persists through entry edits and JSON/CSV exports. See [OCC equity specifications](https://www.theocc.com/clearance-and-settlement/clearing/equity-options-product-specifications) and [OCC weekly premium quotations](https://www.theocc.com/clearance-and-settlement/clearing/weekly-options). Displayed broker net cash includes embedded option fees; expiration realizes remaining option cost with no cash proceeds. Exactly one delivered and one received merger record on the same date form one conversion; complex/cash-bearing mergers require review. Remaining FIFO basis carries to the destination, and source precision can close only a disclosed rounding residual. Converted lots remain in holdings and transaction history but are excluded from decision grades pending benchmark continuity review. Noncash rewards do not also add cash or units; an unverified basis is displayed as unknown. Unsupported transfers/activity and invalid numeric/date fields block the entire commit.

Cash-only mode rejects unfunded purchases/fees. An explicitly selected margin mode records negative cash as a liability without issuing units or allowing stock oversales. A separate estimated-reconstruction policy requires persisted reconciliation notes, an opening owner and an unverified-cash marker. It can retain incomplete early funding and negative cash without fabricated deposits; the first actual capital flow must match the disclosed opening-owner assumption. Pre-capital activity receives no invented owner units. The dashboard shows a persistent estimate banner and all assumptions. Historical NAV proxies, missing cash and inferred reward attribution must be explicit; no accuracy bound is promised. Reconciliation metadata survives JSON export/restore.

Broker Amount is treated as net cash; explicit trade fees are converted to gross plus a separate fee to avoid double counting. A financial import succeeds atomically or none of its ledger changes do. There is no automatic clearing of sample/user data. The synthetic demo is read-only and never saved to the personal ledger.

## Authorized one-shot private data loading

Ordinary browser routes always use ChatGPT identity. The operator utility `lib/server/owner-import.ts` has no route in the final production app. A short-lived `/api/owner-import` route may be deployed for an explicitly authorized migration, then removed from source and redeployed after use. During that migration it is enabled through native Sites runtime secrets only: `OWNER_IMPORT_USER_ID` pins an already established owner record, `OWNER_IMPORT_KEY_HASH` pins a short-lived service key, `OWNER_IMPORT_PAYLOAD_HASH` pins the exact authorized request body, and `OWNER_IMPORT_EXPIRES_AT` limits authorization to less than one hour. Sites service access is a separate platform boundary and supplies no visitor identity; no visitor identity header is fabricated. If an actual visitor identity is present it must match the pinned owner. The endpoint cannot select a user from its request, create an uninitialized ledger or accept another payload; it validates and atomically backs up the target revision. Retries use a persisted payload receipt. Remove all four runtime values and remove the temporary API route from source, then redeploy immediately after use. Verify that the retired route is unreachable; a control-plane configuration update alone is insufficient retirement evidence. No credentials or actual source data belong in Git, build artifacts, migrations or browser bundles. Tests exercise disabled/expired/wrong-key/wrong-payload/wrong-user/conflicting-revision behavior and backup/retry isolation.


## Market data

Yahoo Finance via the maintained `yahoo-finance2` 4.x library is unofficial, can be delayed/rate limited/unavailable and offers no availability or exchange-license guarantee. The app currently supports USD instruments; non-USD quotes are rejected. Standard US symbols and common crypto symbols such as BTC/ETH/SOL are normalized for Yahoo. External wallet/Robinhood crypto import remains the separate open issue #7; manual crypto entries are supported.

Opening the ledger refreshes quotes through a five-minute D1 cache. Explicit refresh follows the same cache policy. Quote fetch time and market timestamp are distinct; failed refreshes retain an explicitly stale cached quote or mark the symbol unavailable. Quotes whose market timestamp is over seven days old are stale even if freshly fetched. Partial valuations hide complete totals and gains while reporting the known priced subtotal. Historical series extend incrementally with an overlap, a six-hour cache and a full refresh when a new split changes adjustments. Missing history produces gaps and withheld grades. Historical refresh is explicit from the chart/decision view and runs as needed to price cash-flow events. Hosting does not imply continuous background price collection; no unattended schedule is installed.

## Export and recovery

Settings offers a complete JSON backup and a spreadsheet-safe CSV report. JSON preserves partners, entries, cash-flow price inputs and import IDs and supports full restore. CSV is a report, not a full-fidelity recovery format. Downloads contain financial records: store them privately and never commit them.

To recover, select one of the previous 20 revisions or upload a JSON backup, type `RESTORE`, then restore. The server rejects reserved/prototype partner identifiers, validates finite derived amounts and replays the backup, then saves the current revision as a recovery point before replacing it. A stale browser cannot overwrite a later change. Shared ownership maps have no object prototype, and the persistence boundary refuses NaN/Infinity instead of letting JSON silently turn financial values into null. For a later hosting migration, use JSON export/restore against an adapter implementing the same scoped ledger contract. No Prisma database file or secret belongs in the deployed bundle.

## Development and repeatable publication

Use Node 24 (minimum 22.13). From `site/`, run `npm run install:ci`, `npm test`, `npm run typecheck`, `npm run lint` and `npm run build`. The Sites plugin's installer/build/source helpers are the preferred authoring flow. For a new local preview, apply the generated SQL once to the preview D1 database using the documented Sites/Wrangler local migration command, then run `npm run dev -- --port 5184`. Do not run seed/reset commands against any populated or hosted database.

GitHub contains the application under `site/`; the Sites source repository is a separate standalone copy of that subtree. To update: edit/test on the GitHub feature branch, commit, copy the tracked Site subtree into its standalone Sites checkout while preserving that checkout's Git history and excluding runtime data, open it with the Sites source helper and a fresh short-lived credential, build/package/push through the helper, then save/deploy the returned exact commit/archive via the native owner-private operation. Keep `.openai/hosting.json`'s project ID unchanged. Verify the Site source tree equals the GitHub `site/` tree and record both commit SHAs in the release evidence. Never copy `.git`, `.wrangler`, `.sites-runtime`, local environment files, databases, CSVs or credentials into public source or publication input.

CI runs root accounting tests/type/lint and the standalone Site's tests/type/lint/production build. Original local Playwright tests now require an explicit disposable `DATABASE_URL=file:/absolute/path/ledger-alpha-e2e.db`; they cannot copy or seed `prisma/dev.db`. Hosted browser QA uses the separate local D1 preview and synthetic records.

This is presentation state only: transactions sort before pagination and import commit uses canonical source records rather than the sorted view.
